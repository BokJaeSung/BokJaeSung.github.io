Kernel Function

5 min · AA

1. 개요#

커널 함수는 커널 이미지와 커널 모듈 안에 있는 C 함수다. 유저 프로그램은 커널 함수를 직접 부를 수 없다. 시스템 콜이나 인터럽트로 커널에 들어온 실행 흐름이 입구 함수부터 차례로 부른다.

  • 요청과 코드 — 시스템 콜이 “실행해 달라"는 요청이라면, 커널 함수는 그 요청을 처리하는 코드다. execve 요청 하나에 커널 함수 수십 개가 차례로 불린다.
  • 개수 — 배포판 커널에는 수만 개가 있다. 대부분은 시스템 콜 이름과 상관없는 내부 함수다.
  • 추적 — kprobe 와 fentry 는 커널 함수의 입구와 출구에 붙는다. 그래서 eBPF 에서 “어디에 붙이는가"는 대개 “어느 커널 함수인가"다.

2. 구조#

2.1. 심볼#

커널 함수는 이름과 주소가 짝지어진 심볼로 커널 안에 기록된다. /proc/kallsyms 에서 볼 수 있고, root 가 아니면 주소가 0 으로 가려진다.

ffffffff8a2c1e30 T __x64_sys_execve
ffffffff8a2c0a50 t do_execveat_common.isra.0
ffffffff8a2bf9c0 t bprm_execve
  • T — 다른 파일에서도 부를 수 있는 함수
  • t — 그 파일 안에서만 쓰는 static 함수. 주소가 있으므로 kprobe 를 붙일 수 있다
  • .isra.0 — 컴파일러가 바꾼 이름(4.2)

2.2. 실행 문맥#

커널 함수는 어떤 길로 불렸는지에 따라 두 문맥 중 하나에서 돈다.

커널 스레드도 프로세스 문맥이다. 이때 current 는 그 커널 스레드 자신이다.

bpf_get_current_pid_tgid() 같은 헬퍼는 current 를 읽는다. 시스템 콜에서 불린 함수에 붙이면 요청한 프로세스가 나오지만, 패킷 수신처럼 인터럽트 문맥에서 불린 함수에 붙이면 관계없는 프로세스가 나온다.

3. 시스템 콜과의 관계#

시스템 콜 하나에는 입구 함수가 하나 있다. 이름은 SYSCALL_DEFINEn 매크로가 아키텍처 접두사를 붙여 만든다(x86-64 는 __x64_sys_<이름>). 입구 함수는 pt_regs 에서 인자를 꺼내 넘기는 얇은 껍데기이고, 실제 일은 그 아래 함수들이 한다.

  • 아래로 갈수록 공유 — do_execveat_common 은 execve 와 execveat 두 시스템 콜이 함께 지난다. 더 아래의 메모리·파일 시스템 함수는 수많은 시스템 콜이 함께 쓴다.
  • 시스템 콜이 아닌 길 — 타이머가 부르는 TCP 재전송, 디스크 완료 인터럽트, kworker 같은 커널 스레드의 일은 시스템 콜 없이 커널 함수만 지난다. 시스템 콜 추적으로는 보이지 않고, 커널 함수나 tracepoint 에 직접 붙여야 보인다.

4. kprobe 를 붙일 수 없는 함수#

kprobe 는 심볼이 있는 함수의 입구에 붙는다. 확인 순서는 다음과 같다.

4.1. 인라인#

컴파일러가 작은 함수나 한 곳에서만 부르는 static 함수를 호출한 자리에 펼쳐 넣으면, 그 함수는 따로 존재하지 않는다. 심볼도 입구도 없어서 kprobe 를 붙일 수 없다. SYSCALL_DEFINEn 이 만드는 __do_sys_execve 는 소스에서부터 inline 으로 선언된다.

소스에 함수가 있어도 빌드 결과에는 없을 수 있고, 커널 버전과 컴파일 옵션마다 결과가 다르다.

4.2. 이름이 바뀐 함수#

GCC 가 최적화하면서 함수의 변형 복사본을 만들면 이름 뒤에 .isra.0, .constprop.0, .part.0 같은 접미사가 붙는다. 이때는 원래 이름으로 kprobe 가 붙지 않고, /proc/kallsyms 에 보이는 접미사 붙은 이름을 써야 한다.

4.3. 금지 목록#

커널이 스스로를 지키려고 kprobe 를 막아 둔 함수가 있다. kprobe 처리 코드 자체, 예외 처리 입구처럼 여기서 다시 kprobe 가 걸리면 끝없이 되풀이되는 함수들이다. 소스에서 NOKPROBE_SYMBOL() 로 표시하고, /sys/kernel/debug/kprobes/blacklist 에서 목록을 볼 수 있다.

fentry 는 ftrace 가 추적할 수 있는 함수(available_filter_functions)에만 붙고, notrace 로 표시된 함수는 여기서 빠진다.

5. 함수 하나에 붙는 자리#

입구와 출구의 갈고리는 실행 중에 만들고, tracepoint 는 개발자가 소스에 넣어 둔 함수에만 있다. 같은 함수라도 받는 값이 다르다 — 입구는 인자, 출구는 반환값, tracepoint 는 개발자가 골라 둔 값이다.

6. 안정성#

커널 내부 함수는 외부와의 약속이 아니다. 버전이 바뀌면 이름이 바뀌거나, 인자가 바뀌거나, 인라인되어 사라진다. 커널 함수에 붙인 도구는 커널을 올릴 때마다 다시 확인해야 한다.

BTF 와 CO-RE 는 구조체 칸의 위치가 바뀌는 문제를 덜어 주지만, 함수가 사라지는 문제는 풀지 못한다.

7. 확인 명령#

sudo grep execve /proc/kallsyms                                  # 심볼과 주소, T · t
sudo wc -l /sys/kernel/tracing/available_filter_functions        # ftrace · fentry 가 붙을 수 있는 함수 수
sudo head /sys/kernel/debug/kprobes/blacklist                    # kprobe 금지 목록
sudo bpftrace -l 'kprobe:*execve*'                               # kprobe 로 붙일 수 있는 이름
