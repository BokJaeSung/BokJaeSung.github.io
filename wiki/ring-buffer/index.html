Ring Buffer

8 min · AA

1. 개요#

링 버퍼(ring buffer)는 정해진 크기의 메모리를 고리처럼 돌려 쓰는 버퍼다. 쓰는 쪽은 끝에 닿으면 처음으로 돌아가고, 읽는 쪽은 쓰는 쪽을 뒤따라 읽는다. 메모리를 더 잡지 않고 끝없이 들어오는 기록을 받을 수 있어, 커널이 유저 공간으로 기록을 넘기는 통로로 쓰인다.

eBPF 프로그램이 유저 공간으로 데이터를 내보낼 때 쓰는 링 버퍼는 세 종류다. 이름은 같은 “링 버퍼"지만 서로 다른 메모리이고, 쓰는 헬퍼와 읽는 창구가 다르다.

앞의 둘은 원래 다른 기능(ftrace, perf)의 통로를 eBPF 가 빌린 것이고, BPF 링 버퍼 맵만 eBPF 를 위해 만든 것이다.

2. 기본 동작#

버퍼에는 쓰는 자리(tail)와 읽을 자리(head)가 있다. 쓰는 쪽이 한 바퀴 돌아 읽을 자리를 따라잡으면 버퍼가 가득 찬 것이다. 이때 어떻게 하는지가 버퍼마다 다르다.

ftrace 링 버퍼는 덮어쓰기를 기본으로 해서, 문제가 난 직전의 기록을 남기는 블랙박스처럼 쓴다. eBPF 전용으로 쓰는 두 버퍼는 이미 쓴 기록을 지키고 새 기록을 버린다. 유저 공간은 놓친 수를 보고 버퍼 크기나 읽는 속도를 조정한다.

3. ftrace 링 버퍼#

커널 추적 기능 ftrace 가 기록을 남기려고 만든 버퍼다. 2008년 ftrace 와 함께 들어왔다. 함수 추적, kprobe 이벤트, tracepoint 가 모두 이 버퍼에 기록한다. 커널 안에서 초당 수십만 건을 기록해도 시스템이 느려지지 않도록 설계되었다.

3.1. 구성#

CPU 마다 4KB 페이지 여러 장을 고리로 이어 둔다. 최상위 인스턴스는 global_trace(struct trace_array)이고, 그 아래 struct trace_buffer 가 CPU 별 고리(ring_buffer_per_cpu)를 가진다.

  • 쓰기 — 각 CPU 가 자기 고리의 tail 페이지에만 쓰므로 잠금이 필요 없다. 인터럽트나 NMI 처리 중에도 기록할 수 있다.
  • 읽기 — head 페이지와 reader 페이지를 맞바꿔, 읽는 쪽이 느려도 쓰는 쪽은 멈추지 않는다. trace_pipe 로 읽은 줄이 버퍼에서 빠지는 이유다.
  • 합치기 — trace_pipe 는 CPU 별로 빼 온 페이지를 타임스탬프 순서로 합쳐 내보낸다. 출력 줄의 [001] 이 CPU 번호다.

3.2. 파일#

tracefs 의 파일로 버퍼를 다룬다. tracefs 는 커널 4.1 부터 /sys/kernel/tracing 에 마운트된다. /sys/kernel/debug/tracing 은 debugfs 를 마운트했을 때 같은 tracefs 가 함께 붙는 호환 경로다.

파일역할
trace_pipe읽기 전용. 읽은 줄은 버퍼에서 빠지고, 새 줄이 올 때까지 기다린다
trace지금 버퍼 내용을 비우지 않고 보여 준다. 빈 문자열을 쓰면 버퍼를 비운다
trace_marker쓰기 전용. 유저 공간이 쓴 문자열이 버퍼에 한 줄로 들어간다
buffer_size_kbCPU 하나의 버퍼 크기
instances/폴더를 만들면 그 인스턴스 전용 버퍼와 파일이 따로 생긴다

파일은 디스크에 없는 가상 파일이다. 읽는 순간 커널 함수(tracing_read_pipe())가 불려 버퍼 내용을 글자로 바꿔 건넨다. 그래서 trace_pipe 로는 ftrace 링 버퍼만 읽을 수 있고, 다른 링 버퍼를 끼워 읽을 수는 없다.

3.3. eBPF 에서의 사용#

eBPF 프로그램은 헬퍼 bpf_trace_printk() 로 이 버퍼에 한 줄을 쓴다. 쓸 버퍼를 고르는 인자가 없어 항상 최상위 버퍼에 쓴다.

  • 형식 문자열에 넣을 수 있는 인자는 최대 3개다.
  • 머신에 하나뿐인 버퍼라 다른 프로그램과 커널 추적 기록이 섞인다.
  • 받는 쪽은 글자 줄을 다시 파싱해야 한다.
  • 이 헬퍼를 쓰는 프로그램이 처음 로드되면 커널이 dmesg 에 디버그 전용이라는 경고를 띄운다.

그래서 eBPF 에서는 “실행됐다"를 확인하는 디버그 출력으로만 쓰고, 데이터는 4·5절의 버퍼로 보낸다.

4. perf 링 버퍼#

성능 분석 도구 perf 의 하위 시스템 perf_events(2009, 커널 2.6.31)가 샘플을 모으려고 만든 버퍼다. perf 는 일정 간격마다 그 순간 CPU 가 실행 중이던 위치와 프로세스를 샘플로 찍어 이 버퍼에 쌓고, 샘플 비율로 어디서 CPU 시간을 쓰는지 계산한다. eBPF 는 커널 4.4 의 헬퍼 bpf_perf_event_output() 로 이 통로에 샘플 대신 구조체를 넣는다.

4.1. 구성#

  • 맵 — BPF_MAP_TYPE_PERF_EVENT_ARRAY 는 링 버퍼가 아니라, CPU 번호마다 그 CPU 의 perf_event 를 적어 둔 목차다.
  • 버퍼 — perf_event 하나마다 링 버퍼 하나가 있다. 첫 장은 메타 페이지(perf_event_mmap_page)로, 쓴 위치 data_head 와 읽은 위치 data_tail 을 둔다. 그 뒤로 데이터 페이지 2ⁿ 장이 이어진다.
  • mmap — 유저 공간이 이 메모리를 그대로 비춰 읽으므로 read() 처럼 복사하지 않는다.

4.2. BCC 에서의 사용#

BPF_PERF_OUTPUT(events);                   // PERF_EVENT_ARRAY 맵 선언
events.perf_submit(ctx, &e, sizeof(e));    // 지금 CPU 의 버퍼에 구조체 e 를 씀

b["events"].open_perf_buffer(print_event)  # CPU 마다 perf_event 를 열고 mmap
while True:
    b.perf_buffer_poll()                   # 기록이 오면 print_event 호출

4.3. 놓친 기록#

버퍼가 가득 차면 새 기록을 버리고, 버린 수를 담은 PERF_RECORD_LOST 기록을 남긴다. BCC 에서는 open_perf_buffer() 의 lost_cb 로 받는다. CPU 마다 버퍼가 따로라 한 CPU 에 기록이 몰리면 그 CPU 버퍼만 넘친다.

5. BPF 링 버퍼#

eBPF 전용으로 만든 맵 BPF_MAP_TYPE_RINGBUF 다. 커널 5.8(2020)에 들어왔다. perf 링 버퍼의 세 가지 불편을 고쳤다.

  • 메모리 — CPU 마다 버퍼를 잡아 CPU 가 많을수록 낭비가 컸다. 하나만 잡는다.
  • 순서 — CPU 버퍼 사이에서 사건 순서가 섞였다. 자리를 잡은 순서대로 읽는다.
  • 복사 — 구조체를 다 만든 뒤 버퍼로 복사해야 했다. 버퍼 안 자리에 바로 쓸 수 있다.

5.1. 구성#

  • 공유 — 모든 CPU 의 프로그램이 버퍼 하나를 쓴다. 자리를 잡을 때만 짧게 잠그고, 다 쓴 뒤 확정할 때는 잠그지 않는다.
  • 끝 넘김 — 데이터 페이지를 가상 메모리에 두 번 연달아 비춰 둔다. 고리 끝에 걸친 기록도 이어진 메모리처럼 읽는다.
  • 알림 — 새 기록이 확정되면 epoll 로 유저 공간을 깨운다. 깨우는 횟수를 줄이는 플래그(BPF_RB_NO_WAKEUP)도 있다.

5.2. 쓰는 두 방식#

방식하는 일조건
bpf_ringbuf_output()스택에 만든 구조체를 버퍼로 복사perf 버퍼와 쓰는 법이 같다
bpf_ringbuf_reserve() → bpf_ringbuf_submit()버퍼 안 자리를 먼저 받아 그 자리에 바로 채움크기가 검증 시점에 정해져야 한다. 받은 자리는 반드시 submit 하거나 discard 한다

자리가 없으면 reserve 가 NULL 을 돌려주고, 그 기록은 버려진다.

5.3. BCC 에서의 사용#

BPF_RINGBUF_OUTPUT(events, 1);                    // 링 버퍼 맵 선언 · 크기 1 페이지
events.ringbuf_output(&e, sizeof(e), 0);          // 복사해 넣기

b["events"].open_ring_buffer(print_event)         # mmap 1개
while True:
    b.ring_buffer_poll()                          # epoll 로 기다렸다가 print_event 호출

7. 확인 명령#

cat /sys/kernel/tracing/buffer_size_kb              # ftrace 버퍼 크기 · CPU 하나당
sudo cat /sys/kernel/tracing/trace_pipe             # ftrace 버퍼 읽기 (읽은 줄은 빠짐)
echo hi | sudo tee /sys/kernel/tracing/trace_marker # 유저 공간에서 한 줄 쓰기
sudo bpftool prog tracelog                          # trace_pipe 와 같은 내용
sudo bpftool map list                               # perf_event_array · ringbuf 맵 확인
sudo dmesg | grep -A3 trace_printk                  # bpf_trace_printk 경고
